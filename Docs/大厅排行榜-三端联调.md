## 2026-10-31 排行榜分类收窄（随1.0.76上线）

本节覆盖历史分类口径：History 仅返回 `Enable=1` 且 `GameType IN (1,3)` 的牌机/拉霸，另排除麻将胡了 `GameId=54`。鱼机、押注、未知类别及关闭游戏的分类和历史一起隐藏。Games 经代理线可玩范围过滤后的编号同时用于 Rows SQL，在 `ORDER BY ... LIMIT 30` 前筛选，避免隐藏记录挤占 30 条；无可见游戏使用空结果条件，直接请求隐藏编号同样返回空记录。原中奖上报、历史存储、分数、游戏开关与代理线记录隔离保持既有口径，无 SQL 迁移或游戏服更换。

配套客户端同样过滤，兼容尚未部署此后台的环境。客户端仅选具体游戏，首个游戏关闭后选下一可见游戏，全部不可见时清空选择。后台发布即可让现有历史榜客户端收到筛选后的分类和记录；客户端兜底随下次 APK 发布。本轮仅修改并验证本地源码，没有线上部署。

## 2026-10-29 四列排版配套接口（未发布）

客户端改为「玩家 / 机台号 / 奖项 / 分数」，左侧牌机 → 拉霸 → 鱼机，既有押分游戏保留末尾。History 响应新增 `Games[].GameType` 与 `Rows[].PlayerAccount/Machine`，既有字段继续保留兼容旧客户端。`PlayerAccount` 直接从中奖账号按客户端鱼机规则匿名（前两位 + `..` + 后两位，例如 `77123418` → `77..18`），不下发完整账号；短值、空值、组合文字与鱼机一致。

`Machine` 按同一 EventId 与游戏编号关联 gameprizerecord 的 RoomId/TableId，牌机/鱼机按原 1 基编号，拉霸的 0 基编号加一，非首房间带场次前缀。明细过期清理后仍保留排行榜记录，未知机台显示 `--`。无需表结构或游戏服变更；七天前已清理的机台信息无法补造。新客户端遇到旧接口时，账号显示 `..`，机台显示 `--`，仍能显示奖项及分数。

本轮后台编译通过，30 项 API 检查、10 项 Poco 存储检查通过；实际生产 HTTP → Unity RefreshLoop 验证 11.05 秒，覆盖真人/机器人账号、5 秒刷新、分类切换与开关过滤，验证进程含等待共 24.65 秒。专用本地库已删除，业务库未改；未发布线上后台或客户端包。客户端预览及最短人工验收见配套仓库 `MTH-git/Docs/大厅排行榜-历史中奖记录.md`。

全部视图及每款启用游戏按中奖时间倒序展示最新 30 条，真人、机器人共用真实结算上报与查询，关闭游戏后分类及两类玩家的记录一起隐藏。客户端保持恢复后的原始深色外观。

接口为 `GET /Api/RankingList/History?gameId=0`，返回 `Games/Rows/Limit`。`games.Enable=1` 在 SQL 查询内过滤，`RecTime DESC,ID DESC LIMIT 30` 决定顺序，分数用字符串保留精度，不公开账号或控牌字段。中心服将中奖明细与 `gamerankhistory` 在同一事务内写入，每游戏 30 槽循环覆盖，重复事件不推进，七天明细清理不清空榜单。

迁移：`Docs/sql/大厅排行榜最新30条-20261027.sql` 创建独立表并幂等回填。未曾上报的旧机器人中奖无法补造，更新游戏服后开始保留真实记录。客户端每次请求结束 5 秒刷新，分类切换清空旧行、过期请求不覆盖新分类，关闭停止请求，不接受旧财富榜的 HTTP 200 数组或缺失历史字段。
