# 大厅排行榜三端联调（2026-10-28）

## 2026-11-06 按实际专属/公共桌隔离（本地已验证，未部署）

本节替代旧的“本线记录＋公共记录”合并规则。需求以莫线为例，实际实现适用于各代理线：

| 玩家所处范围 | 排行榜及大奖播报 |
|---|---|
| 火凤凰已分配莫线专属桌 | 只看这些专属桌的真人/机器人记录及播报，不混公共桌或其他线专属桌 |
| 大字板没有莫线专属桌，使用公共桌 | 看公共桌真人/机器人，包括其他代理线真人在公共桌产生的记录；排除其他线专属桌 |
| 游戏未开放或不在本线可玩列表 | 分类、记录及机器人播报均不展示；直接请求游戏 ID 也不能越过筛选 |

### 实现与不变量

- `TableDisplayMap.HistoryVisibilitySql` 将实际可见桌转回中奖协议坐标，SQL 在取最新 30 条之前筛选，原生房间内 1 基桌号与拉霸全局 0 基下标分别处理。保留当前工作区已有台号映射，显示“1号机”不代表不同线共用同一真实桌。
- `History` 必须提供存在的玩家 `account`；缺失或未知账号返回 400，不能再退回跨线混合榜。现有客户端 `Network.AccountQuery` 已携带账号，无需为这条规则修改客户端。
- `LineScope::PrizeLine` 将真人与机器人都归到中奖桌的所属线，公共桌统一为空串。中心接收无归属尾段的旧上报时，`ResolveLegacyTableLine` 根据真实房间/桌号查询配置，不拿玩家代理线猜桌台归属；不存在的桌不生成大奖榜/播报，普通明细保留。
- 中心播报附加来源游戏的开放状态及有专属桌的代理线集合；大厅与各支持代理线协议的游戏接收端都按来源游戏判断有效范围，再交集玩家可玩游戏。不能用接收玩家当前游戏的桌配置判断跨游戏播报。桌台归属推送同时发送空正文的范围快照，更新已排队消息的过滤范围；空正文不入队。断线重建清除旧快照，缺失/截断快照不放行大奖。
- `AnnouncementsController` 保留游戏开放/玩家可玩检查；`AnnouncementRules` 的真人和机器人均检查实际可见桌，机器人继续执行已有占座检查。没有改变奖项、倍率、分数、结算、奖池或机器人调度。
- 环形表新增可空 `RoomId/TableId`，新事件与记录同事务保存，覆盖槽位时一并覆盖。旧记录仅从同一 `EventId + GameId` 的现存明细补坐标；无法恢复坐标的历史记录保留在库内，但不进入需要桌台隔离的客户端榜单。后续明细清理不会再导致新榜单丢失桌台身份。

## 2026-10-29 四列排版配套接口（未发布）

客户端改为「玩家 / 机台号 / 奖项 / 分数」，左侧牌机 → 拉霸 → 鱼机，既有押分游戏保留末尾。History 响应新增 `Games[].GameType` 与 `Rows[].PlayerAccount/Machine`，既有字段继续保留兼容旧客户端。`PlayerAccount` 直接从中奖账号按客户端鱼机规则匿名（前两位 + `..` + 后两位，例如 `77123418` → `77..18`），不下发完整账号；短值、空值、组合文字与鱼机一致。
