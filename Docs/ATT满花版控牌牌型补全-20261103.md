# ATT 满花版控牌牌型补全

2026-11-03 已本地实现并验证，未发布。GameId=25，cardAction=8。

原后台把 ATT 满花版当作点石成金的通用牌型，只列基础牌型，还隐藏了大四梅。服务端已有满花、方块彩金、金拇指的自然开奖与派奖，但控值只支持 0～12，中心服和后台校验也会拒绝扩展控值。因此本次同时补后台目录、校验、中心转发与 ATT 实际开奖，不能只发布页面。

## 选项和规则

共提供 29 个送牌选项及 99=关闭；基础值 1～11 保持原编号（恢复 8=大四梅），新增以下 18 项。倍率是基础押注赔付，彩金另加，仍按原小/中/大三档 60%/25%/15% 抽档。

| 控值 | 牌型 | 基础赔付 | 附加彩金 |
|---|---|---|---|
| 13 | 普通满花·三条 | 6 倍 | 无 |
| 14 | 普通满花·杂顺 | 8～12 倍 | 无 |
| 15 | 普通满花·葫芦 | 16～24 倍 | 无 |
| 16 | 普通满花·大四梅 | 80～120 倍 | 四梅池 |
| 17 | 普通满花·五梅 | 600～1000 倍 | 五梅池 |
| 18 | 普通满花·同花大顺 | 300～500 倍 | 大顺池 |
| 19 | 正宗满花·两对 | 6 倍 | 满花池 |
| 20 | 正宗满花·三条 | 9 倍 | 满花池 |
| 21 | 正宗满花·葫芦 | 24～36 倍 | 满花池 |
| 22 | 正宗满花·大四梅 | 120～180 倍 | 四梅池及满花池 |
| 23 | 方块彩金·同花 | 6～8 倍 | 方块池 |
| 24 | 方块彩金·同花顺 | 100～140 倍 | 顺池及方块池 |
| 25 | 方块彩金·同花大顺 | 150～250 倍 | 大顺池及方块池 |
| 26～30 | 金拇指 | 分别 20/50/100/200/400 倍 | 无 |

普通满花为 J/Q/K 与鬼组成的五张牌（必须含鬼，非全鬼），基础牌型赔付 ×2。正宗满花为五张全 J/Q/K、无鬼，基础赔付 ×3 并领取满花池。按真实牌型判定，普通满花不可能组成两对或小四梅；正宗满花不可能组成五梅、顺子或同花，因此没有添加这些虚假组合。杂牌和五鬼继续不提供。

## 实现

- `Scripts/app/game.attmhb-controls.js` 为 ATT 独立目录，手机、电脑用户管理及在线玩家共用；历史回显沿用现有函数。各页面按 WebVer 引用，新增文件已登记旧式 csproj。
- `card-prize-quotes.json` 的 ATT 项与共享目录一致；变动赔率标记 Estimated，按最高基础赔率、可能叠加的满花倍率及奖池上限保守报价。派奖仍走实际金额，未把估值当作实际扣款。
- `B_UserControl` 与中心服允许 action=8 的 13～30，99 关闭及其他游戏的现有范围保留。
- ATT 扩展控牌仅在原 N 把内 M 次概率门命中时生效，消费原控牌次数，保留送奖 ControlId。特殊控值与基础枚举分开匹配，避免成功发牌后不消耗次数。
- 满花/方块选项首手生成满足牌型的真实牌面，结算保持该牌面，所有留牌组合都保留已留的牌并确保目标结果。金拇指沿用现有客户端协议，所选位置命中指定档位，五个位置仍展示五档的完整排列；未选或多选沿用随机代选。
- 不扩展持久化算法结构，不改 SQL、APK、普通自然概率、桌台配置或已落库记录。

旧权重测试曾断言“关闭满花升级权重后，自然两对绝不能是满花”。这与自然开牌规则不符：同一随机种子 `1793702478` 下，Git HEAD 和改后源代码输出完全相同，均自然出现两次满花而失败。本次将该断言改为已知非满花牌面的直接不变性检查，并固定种子 `20261103`，未修改自然出牌算法来迎合断言。

```powershell

node .build/check-attmhb-browser.cjs

```

目录调整后可用 `node .build/check-attmhb.cjs --export` 仅更新 ATT 报价；其他游戏报价保留。测试结果 `TestResults/attmhb-controls.trx`，截图 `.build/attmhb-control-mobile.png`。
