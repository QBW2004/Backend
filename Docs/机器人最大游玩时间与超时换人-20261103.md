## 操作与规则

入口：电脑后台「机器人管理 → 自动调度 → 最大游玩时间」。总台可以保存，沿用现有机器人管理的登录鉴权与超级管理员写权限。

- 勾选「启用超时换人」，设置最小、最大小时数；支持 0.1～720 小时、一位小数，两个值相同表示固定时长。
- 每次机器人收到成功入座回执时开始计时，在所设范围内为本次入座随机抽取游玩上限。连接中、登录中及等待座位的时间不计入。
- 超时后随机等待 60～300 秒，原机器人继续在座；等待结束后，从未分配运行时座位的账号池随机选另一个机器人，接替原游戏、房间、机台和座位。正常调度约每秒检查一次。
- 接替者保留原机器人的配置行、代理线配额与随机选台锚点，首次入座只请求原实际座位。旧服务端若回执到其他座位，立即断开重试；目标座位暂时被占时等待原座位，不挤掉真人。
- 没有空闲账号时保留原机器人，每 60 秒重试；正在连接、等待座位的账号已占用配额，不能被其他座位抢用。需在账户管理中准备多于同时入座数的账号。
- 保存后立即生效；调整范围时保留已经游玩的时间，重新抽取上限与后续等待。重复保存同一范围不刷新计时。关闭后取消待执行换人。
- 断线重连成功入座、手动移动、每日打乱后的入座均开启新一轮计时。Robot 进程重启后从新入座计时；计时不写数据库。
- 每日打乱与超时换人各自独立，生命周期互斥防止重复创建、删除或同时移动同一机器人。每日打乱执行期间推迟超时换人。

## 配置与改动

沿用 Robot 正在读取的 `robot.ini`，新增三个键，先原子落盘、成功后更新运行态；保留全部既有键。缺省关闭，不替运营启用。

```ini
playTimeEnabled=0
playTimeMinSeconds=7200
playTimeMaxSeconds=14400
```

管道新增 `PLAYTIME_GET` → `PLAYTIME_JSON {...}`，以及 `PLAYTIME <0|1> <minSeconds> <maxSeconds>` → `PLAYTIME_OK/PLAYTIME_BAD`。C# 与 C++ 均验证范围、精度与顺序；无效参数或落盘失败不改变运行态。后台遇到旧版 Robot、不完整数据或读取失败，禁止保存默认值覆盖真实设置。

后台产品改动：`RobotController.cs`、`Areas/Game/Views/Robot/Index.cshtml`。Robot 产品改动：`ServerRun.*`、`UserRobot.*` 与 `RobotPlayTime.h`；新头文件登记进工程和 filters。无新增 BLL 依赖。

## 发布与人工验收

以下为 11 月 3 日实现时拟定的发布与人工验收流程。功能现已随后台 1.0.99 发布，实际记录见 `后台1.0.99与批量修复发布-20261103`；11 月 4 日核查结果见本文顶部。

1. 备份当前后台、Robot 程序和 `robot.ini`，按既定流程打包后台；WebVer 递增。
2. 仅停止并更新 ServerRobot 的 exe/PDB，保留原 `robot.ini`，确认只有一个 Robot 进程；无需重启中心服或子游戏。再发布后台 `YYT.Web.dll`、Robot 页面及版本文件。
3. 总台进入「自动调度」，读取未启用的默认范围 2～4 小时；设置运营要求的范围并保存，重新读取确认。
4. 保留至少一个未分配运行时座位的机器人账号。在测试场景设 0.1～0.1 小时，成功入座 6 分钟后再等 1～5 分钟，核对旧 ID 被空闲 ID 替换、游戏/机台/座位相同且配置目标人数不变。测试后恢复运营设置。
5. 若已被真人占座、网络故障、每日打乱执行中或无空闲账号，换人可能延期；用 `[Robot-PlayTimeWait]`、`[Robot-PlayTimeReplace]`、`[Robot-PlayTimeSeatMismatch]` 日志核对，不使用线上真实玩家座位做强制换人测试。

快速回滚可先在后台关闭超时换人；程序回滚恢复备份 exe/PDB。旧 Robot 会忽略新增 ini 键，旧每日打乱设置保留。
