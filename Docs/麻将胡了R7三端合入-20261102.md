## 针对当前版本补的兼容修复

1. 当前送奖协议已有 `Int32 prizeControlId`，R7 又增加两个 64 位控制快照。游戏 54 的登录/控制尾段统一为 `Int32 prizeControlId + UInt64 giftId + UInt64 totalKillId`，即 20 字节；无送奖时也保留 0 槽位。其他游戏维持现有协议。校验覆盖登录、解除、赠送、吃分、高位 ID 及损坏长度。
2. 游戏 54 停用旧独立钱包保存、旧 BetSync 和旧消费通知，改由恢复事务唯一入账，避免新旧路径重复记账。其他游戏仍走当前逻辑。
3. 恢复事务继续写当前 `user_winloss_ledger` 和日汇总，按 `score_per_coin × 200 ticks` 换算钻石，保留小额奖金，并用稳定事件号去重。
4. 接入当前代理送奖奖池的两条存储过程。赠送和放水重叠时只扣一次；原赠送获得的免费链持久保存资金归属，重连或更换赠送不改扣新奖池。奖池失败时钱包、操作收据及盈亏账一起回滚。
5. 总吃分/放水仍按钻累计，小数余数随恢复行保存；保留当前非麻将游戏的总控支持、清理及奖池耗尽处理。
6. 新事务成功后继续更新实时押注钻石报价，小额押注、免费押注均带实际兑换比；重放旧请求不覆盖新报价。
