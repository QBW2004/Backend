客户端需求：注册后进入大厅自动提示设置昵称；关闭不代表完成，下次进入仍提示；是否完成由服务端持久化判断。

## 变更

- 迁移 `Docs/sql/玩家昵称设置标记-20261101.sql` 给 `users` 新增 `NICKNAME_SET TINYINT NOT NULL DEFAULT 0`。现有中心服注册未指定该字段，默认未设置，无须更换游戏服或改 TCP。
- `B_Users.GetNicknameState` 按账号与密码查询标记，`POST /Api/UpdateUsers/NicknameStatus` 返回 `code=10000,datas={name,nicknameSet}`，其中 `nicknameSet` 是布尔值。鉴权失败或数据库异常返回非 10000，不返回虚假的已完成状态。
- 原 `POST /Api/UpdateUsers` 保存接口统一校验空白、1～8 字符及合法字符；`B_Users.updateUsersName` 用同一条参数化 SQL 更新昵称与标记，更新时再次校验密码。成功响应不回显密码，保留旧客户端使用的 `datas.name`。
- 没有把新增数据库字段加入通用 EF 玩家实体，避免不相关业务读取新增列；昵称查询和更新集中使用参数化 SQL。

## 存量与重复迁移

首次迁移将非空、去除两端空白后不同于账号的存量昵称标记为已设置；账号默认昵称和空白继续提示。历史无设置记录，曾主动改为账号本身的老玩家会提示一次。之后只按标记判断，主动保存为账号本身也算完成。

重复执行 SQL 不再次回填，因此不会把新注册但未主动设置的玩家误记完成。删除玩家后重注册自然回到默认 0，没有额外按账号残留表。
