# 大白兔规则读取与 JSON 回包修复

2026-11-04：本地修复与验证完成，未发布，未修改线上数据、配置或进程。

## 问题与修复

大白兔桌台的小四梅、大四梅、五梅持续显示“等待有效规则”，RTP 显示“—”，底部停在“正在读取玩法规则…”。GetRabbitConfig 把 Json.NET 反序列化得到的 JObject 交给 MVC JsonResult；后者实际使用 JavaScriptSerializer，将 JToken 枚举成嵌套数组，字段名和值在 HTTP 回包中丢失。前端的校验异常随后又被“已载入”状态覆盖。

- GetRabbitConfig 改用 JavaScriptSerializer.DeserializeObject，直接返回与 MVC 序列化器兼容的字典、数组和标量。兼容 GetRabbitPayoutRules 同步受益。火凤凰 GetPhenixConfig 有相同问题，一并修复这一个读取点；没有改全站 JSON 序列化行为。
- 大白兔前端拒绝数组、空值等异常规则回包；载入后的模型和表单校验必须成功才能显示“已载入”。加载、校验和网络失败统一清空 RTP、显示具体原因并禁止保存；请求最长等待 15 秒，可通过顶部刷新重试。旧桌迟到响应仍受请求序号与桌号保护。
- 已保存规则、每桌隔离、倍率、概率、隐藏留机参数、统一保存事务及游戏服协议不变。未变更 SQL、中心服、游戏服或 APK。

## 验证

旧版真实 Controller 经 JsonResult.ExecuteResult 输出 HTTP JSON 后，原测试在读取 smallFourMultiplier 时失败（config 为 JArray），与浏览器截图复现一致。原测试直接使用 JObject.FromObject(JsonResult.Data)，绕过了出错的序列化阶段；现已改成执行实际 MVC HTTP 输出后再验证。

| 检查 | 结果与耗时 |
| --- | --- |
| Release 构建 | 通过，约 2.1 秒；仅 5 条已有警告 |
| 实际 Controller / MVC HTTP 序列化 / 隔离 MySQL / 模拟管道 | 291 项，5.12 秒；包含独立桌保存、完整回滚、隐藏字段和火凤凰默认/存量规则回包 |
| 实际 MVC 回包驱动 Chromium | 31 项，2.07 秒；正常倍率/RTP、异常数组/空值/字段、表单校验、业务失败、断网、坏 JSON、超时、刷新恢复和迟到失败隔离 |
| 全字段 Chromium | 182 项，2.75 秒；从实际 Controller 经 HTTP 序列化生成的两桌数据逐字段加载和提交 |
| 既有大白兔与相邻界面 Chromium | 74 项，4.99 秒 |
| 视图契约与活动逻辑 MSTest | 99 项，0.95 秒 |

测试 MySQL 仅用本机 127.0.0.1:33308、临时 mth_rabbit_rules_fixture_* 数据库和独立命名管道；临时库已清理。初次测试服务未指定 UTF-8，中文桌名回滚断言失败；按项目要求以 utf8mb4 重启该测试实例后全部通过。

复验入口依次为 Tools/dev/check-rabbit-rules.ps1、node Tools/dev/check-rabbit-json-ui.cjs、node Tools/dev/check-rabbit-all-parameters-ui.cjs。现有 UI 回归入口仍为 node Tools/dev/check-rabbit-rules-ui.cjs。

证据在 .build/rabbit-rules-validation/：rabbit-default-response.json、phenix-stored-response.json、json-browser-checks.json、rabbit-json-fixed.png；契约报告为 TestResults/rabbit-json-wire-20261104.trx。
