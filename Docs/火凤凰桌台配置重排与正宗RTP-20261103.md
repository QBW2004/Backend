# 火凤凰桌台配置重排与正宗 RTP

2026-11-03：本地实现，供交互预览，未发布。

火凤凰桌台页改为紧凑牌型表和正宗翻倍权重表；移除 JSON 展示和独立保存按钮。权重表展示档位、权重、抽中概率、奖励倍数、理论 RTP 贡献；顶部展示基础 RTP、翻倍增量、综合理论 RTP 和平均奖励。统一使用底部“保存并热更新”。

计算：正宗平均倍数为 Σ(档位×权重)÷权重合计，乘基础80倍后替换大四梅原80倍，避免重复计算。关闭正宗后回到普通80倍；停用大四梅时相关贡献为0。小四梅按40档估算，页面明确提示40/50实际档位；理论值不等于玩家保留换牌后的实测返奖率，不包含控牌和旧难度强放。

示例数据：大四梅出现机会5/10000，X1/X2/X3权重60/30/10，平均奖励120倍；基础80.30%，正宗增量2.00个百分点，综合82.30%。这些仅为预览数据。

`PhenixConfigJson` 随 `SaveTableConfig` 提交。火凤凰基础、难度、牌型概率与独立规则在同一事务保存。校验档位唯一、非负整数权重、权重合计和最高押分容量，保留未知字段；旧页面不携规则时保留现存值。加载失败拒绝提交，处理重复点击、请求失败重试及切换桌台后的迟到响应。保留原权限与防伪校验。

服务端配套：`../MTH-Server/ServerCardPhenix/Alg/CardAlg.cpp` 在 `gp_profile_on` 模式下抽中大四梅且无指定控牌时，根据正宗开关和权重抽取翻倍。旧代码在桌台权重模式跳过正宗分支，因此只发布页面会造成计算和结算不一致。原难度排期及控牌X1～X6保持原逻辑。

验证：Release后台构建、10项火凤凰/代理线契约、18项JS数学检查、26项真实Chromium交互检查、18项实际Controller/独立MySQL检查通过。隔离库验证规则回读、未知键、旧页面兼容、整数/容量校验、后续SQL失败时基础/规则/概率整组回滚；测试库已清理。服务端Release x64和真实CardAlg专项通过，覆盖10000次档位抽样、X14全流程结算、关闭正宗、默认值与指定控牌。全站Razor预编译通过，验证副本排除既有缺失FengBo依赖的死代码视图，只有既有不可达代码警告。耗时和日志位于 `.build/phenix-redesign-20261103/`。
