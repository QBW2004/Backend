# 客户端修改说明：客服链接（「客户」按钮）空值处理

> 交接对象：客户端对接人员
> 关联服务端：后台 `YYT.Web`（`/api/CustomerServiceUrl` 接口行为已调整）

---

## 一、背景与问题现象

客户端大厅底部的「客户」（客服）按钮，点击后调用后台接口获取客服链接并跳转浏览器。

**原现象**：当玩家所属代理**未配置**客服链接时，点击「客户」会打开**总代理（平台最高级）配置的链接**。原因：服务端此前做了「客服链接回退」——直属代理没配链接时，会沿代理层级逐级向上查找，命中上级/平台默认已配置的链接后返回。

**业务诉求**：代理未配置链接时，不应弹上级/总代理的链接。

## 二、服务端已做的调整（背景，无需客户端实现）

服务端 `ResolveCustomerServiceUrl` 已去掉「链路上溯 + 平台兜底」逻辑，改为：

- **仅取玩家直属代理配置的客服链接**；
- 直属代理未配置 / 不存在 → 返回**空字符串**（接口仍返回 `code=10000` 成功）。

即：代理没配链接时，接口返回成功但 `CustomerServiceUrl` 为空串。

## 三、客户端需要修改的内容

### 3.1 涉及文件

```
Assets/WGM/DaTingG178/Script/UI/UIBottom.cs
```

对应逻辑：`OnChat()` → `ToGetGameDownload()`（协程），调用 `POST /api/CustomerServiceUrl`，`code==10000` 时取 `data["datas"]["CustomerServiceUrl"]` 并 `Application.OpenURL(...)`。

### 3.2 需要处理的新分支

由于服务端现在会返回**空串**，客户端需在打开链接前增加空值判断：链接为空时**弹提示**，不再执行 `Application.OpenURL`（避免打开空 URL / 无反应）。

### 3.3 改动后代码（示例）

```csharp
if ((int)data["code"] == 10000)
{
    //成功
    string url2 = data["datas"]["CustomerServiceUrl"].ToString();
    if (string.IsNullOrEmpty(url2))
    {
        ViewMgr.Get.ShowTips("当前代理未配置客服链接");
    }
    else
    {
        Application.OpenURL(OpenWeb.FormatUrl(url2));
    }
}
```

要点：

1. `url2` 取到后先判空（`string.IsNullOrEmpty`），空 → 弹提示，不打开链接；
2. 非空 → 维持原逻辑 `OpenWeb.FormatUrl(url2)` 后 `Application.OpenURL`；
3. 提示文案「当前代理未配置客服链接」可自行调整，但建议保留「未配置」语义，便于玩家联系代理；
4. `ViewMgr.Get.ShowTips(...)` 为项目现有提示方式，已在该文件多处使用，直接沿用即可。

### 3.4 兼容性

- 代理已配置链接：行为不变，正常跳转；
- 代理未配置链接：弹提示，不跳转、不弹上级/总代理链接；
- 该接口全客户端仅此一处调用（`UIBottom.cs`），无其他入口需同步修改。

## 四、验证方法

1. 使用**未配置**客服链接的代理下的测试账号（如代理 `10086` 下的 `t10086`）登录；
2. 点击「客户」按钮 → 应弹提示「当前代理未配置客服链接」，**不**跳转任何页面；
3. 在后台为该代理配置客服链接后，同一账号再点「客户」→ 应正常打开该代理配置的链接；
4. 回归：其他入口（充值、提现等依赖 `OpenWeb.FormatUrl` 的跳转）不受影响。

## 五、备注

- 服务端接口地址不变：`POST http://{ip}:8081/api/CustomerServiceUrl`，请求体 `{"playerId":"玩家账号"}`；
- 响应示例（代理未配置时）：`{"code":10000,"content":"查询成功！","datas":{"CustomerServiceUrl":""}}`；
- 客户端本次改动仅涉及客服链接这一个入口，未触碰其他业务逻辑。
