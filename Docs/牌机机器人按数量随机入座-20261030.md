# 牌机机器人按数量增加与随机入座

状态：2026-10-30 20:37 已随后台1.0.72与服务端配套上线。发布、备份及验收见[牌机机器人发布-20261030](牌机机器人发布-20261030.md)。

## 操作行为

「机器人设置 → 添加机器人」选择牌机后，不再选择桌号，改为填写「增加机器人数」。选择游戏、代理线后显示启用机台总数、已设置机器人数、还可增加的数量。单次增加及累计数量都不能超过所选游戏、本线的启用机台数量，至少增加一个。服务端重新查库校验，同一游戏的并发增加串行处理。

例如本线启用 10 台、已设 4 个，可增加 1～6 个；再增加 7 个会被拒绝。已有的机器人名额计入总数，删除名额后可以补加。禁用机台、其它代理线及已收回桌台不计可用机台；机台减少后超出的存量配置不会自动删库，机器人服务规划时会按新机台数量限制实际运行人数。

机器人在所选线内随机遍历启用机台，收到占用拒绝后尝试下一台；全部占用时等待，后续出现空位再入座。每台只容纳一个牌机机器人，机器人不能互相顶替，真人仍可顶替机器人。随机候选在机器人热更时更新。机器人配置的桌号只作为名额所属线的锚点，实际桌号由游戏服确认；列表显示「随机空机台」。当前删除、禁用或转移锚点桌时，仍按原有桌台配置流程删除、暂停或转移该名额。

适用于火凤凰(5)、大字板(15)、ATT满花版(25)、点石成金(37)、NBA(44)。麻将胡了(54)按本轮用户确认不使用机器人，已从添加选项排除，直接提交也会拒绝。鱼机、押注、拉霸的添加方式保持原口径。

## 验证结果

- 后台 Release 增量构建通过，约 1～5 秒；ServerRobot 与五款牌机 MSVC Release x64 均通过。
- 新增 4 项数量规划单测，连同权限、页面契约、代理线逻辑共 85 项适用测试通过，测试回合 1.06 秒。全量首次选择的 87 项中，两项既有拉霸控牌命名/选项断言不符合当前工作区，未修改或掩盖：`CardControlNamingIsSharedBetweenControlAndPlayerList`、`CardControlOptionsHideZeroPairAndJackpotsOverTwoThousand`。
- 独立本地临时库 24 项实际 BLL 验证通过，3.54 秒：范围过滤、累计上限、并发提交、精确上限、禁用桌、删除后补加、麻将及非牌机拒绝。测试库自动删除，不使用资金/玩家表。
- `node Tools/dev/check-card-robot.js` 执行实际页面脚本通过：数量输入、剩余上限、过期异步响应、满额、请求参数和游戏类型切换。
- 页面 Razor 隔离预编译通过，约 3.5 秒。
- `MTH-Server/tests/build_card_robot_tests.bat`：随机候选遍历、0/255 高低桌号、候选热更、实际 UserRobot 对象 TCP 回环协议；连续 30 次占用拒绝仍可换台并接收入座成功回包，空候选不发坐下、鱼机拒绝路径保留。

## 人工验收（部署后在专用测试线操作）

1. 设 5 台启用机台，添加 3 个，确认显示已设 3、可再加 2；输入 0 或 3 应拒绝，再添加 2 应成功，满额后不能再加。切到鱼机确认仍显示选桌；牌机下拉应没有麻将胡了。
2. 测试玩家先占一台，再添加机器人。确认机器人只坐本线空台、不会互顶或挤占真人。将全线机台占满，确认机器人等待；释放一台后确认机器人最终补位。
3. 切到另一测试代理线，确认数量单独统计且实际入座不串线；禁用机台后不能随机选中该台。验收结束删除本轮新增测试名额。
