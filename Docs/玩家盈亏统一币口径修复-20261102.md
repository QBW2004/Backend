# 玩家今日/总盈亏修复（2026-11-02，已实现、未发布）

> SQL 归档说明（2026-11-05）：本页涉及的历史 SQL 已移至仓库外，原发布/验收事实保持不变；原文位置见 [归档索引](../Database/legacy-sql-archive.md)。当前初始化以 Database/README.md 为准，不按历史清单重跑。

本轮修复核查记录中的单位混用、离场收奖漏计及电脑首屏总盈亏为0，并补齐回本归零、迟到的踢人结算、数据库失败重试、小数显示和旧在线接口的口径。

**当前状态：代码与验证完成；没有发布，没有修改线上历史盈亏。** 当前工作区还有水果双奖池、昵称标记、控牌等其他改动，不能直接拿工作区整包上线。发布须以线上1.0.95为基线隔离构建本轮变化。

## 生效后的统计规则

- 今日盈亏/总盈亏均为玩家实际游戏输赢，赢正输负，单位为币，保留最多8位小数。充值、退币、上下分转换不作为游戏盈亏。
- 游戏服保留原有原始累计输赢；`COM_PLAYER_BET_SYNC` 尾部额外上报 `UInt32 unitsPerCoin` 和 `UInt64 loginSession`。兑换比来自游戏服实际使用的桌台参数，而非后台按游戏名称猜测。旧消息头、当前押注和原始输赢字段保持原样。
- 中心服按相邻累计值之差记增量，按收到结算的UTC+8日期分桶，再以该笔上报的实际比例换算成币。跨桌改比例分桶记录，回本为0照常冲回之前的增量。
- 原有吃分/放水进度计算继续使用既定控制单位；本轮币统计不改变控牌指令、赔付算法或下注金额。
- 牌机离场自动收奖及大白兔活动奖加入最后一次输赢同步；鱼机离场强制补发最终值，避免一秒节流漏掉最后一笔。
- 新增 `user_winloss_ledger` 留存原始增量、兑换比、币增量、日期、游戏、会话和批次ID；同一事务更新日累计。失败保留同一批次ID重试，重复提交不会重复加账；事务连接禁用自动重连，防止断线后半笔提交。
- 仍按既有约10秒节奏批量落库，正常离场补刷。批次在提交前保存在中心服内存，非正常进程崩溃仍存在未刷批次丢失窗口；本轮没有宣称实现完整的逐局持久化故障恢复。

## 后台修改

1. `GetUsersList` 首屏及旧 `GetOnlinePlayersList` 都补齐今日/累计游戏盈亏。
2. `GetOnlinePlayers` 不再以充值减退币覆盖总盈亏；首屏合计同时补齐今日盈亏。
3. 玩家DTO、详情、会员统计、在线补充字段及聚合查询改用decimal，去掉盈亏求和的SIGNED强转。
4. 手机 `M.gold` 保留币的小数；电脑合计显示限制到8位精度，避免JS浮点相加出现长尾。
5. 删除玩家时一并清理新盈亏台账，继续遵守删号清档的既有约定。

## 配套发布顺序

必须配套 **SQL + 后台 + 中心服 + 当前14款在服子游戏**，无需APK。不能只换后台或只换中心服。旧子游戏没有兑换比尾段，新中心服不会把这类报文猜算成新币台账。

当前14款为：彩金单挑、金蟾捕鱼、火凤凰、幸运六狮、李逵劈鱼、大字版、明星97、ATT满花版、点石成金、水果拉霸、NBA、水浒传、麻将胡了、大白兔。

1. 以线上版本建立隔离源码与发布包，仅带入本轮改动；本轮工作区构建产物用于验证，不能直接当隔离发布包。
2. 按既定流程完整备份数据库（带routines/triggers）及旧后台、中心服、子游戏、运行配置与进程清单。
3. 安排停服窗口，先让子游戏完成离场结算，再停止中心服；中心服换版会断开在服玩家。
4. 执行 `Docs/sql/玩家盈亏统一币口径-20261102.sql`。它将WINLOSS扩为DECIMAL(28,8)并创建审计台账，**保留旧值，不会把历史记录自动除100**。
5. 换配套后台及中心/子游戏，后台增加WebVer，使手机版金额脚本缓存失效；按既定流程恢复服务。
6. 核实进程路径、数量、端口及HTTPS，核对文件哈希；比对同刻后台列表/详情/会员统计与日累计，验证新台账与新日增量相等。验证只读，不拿真实玩家做测试下注。

如果要回滚，应将所有配套程序一起处理，保留数据库完整备份与新台账。新小数已经入库后，旧BLL的long字段无法继续正确读取这部分金额，不能只回滚DLL；须先审核新版本期间账目并明确数据库恢复方案。不要把WINLOSS强制改回BIGINT来掩盖兼容问题。

## 历史数据处理

目前线上日累计混合了不同游戏的分/币，且存在退出收奖遗漏，不能直接整表除100，也不能以充值减退币或当前余额替代历史游戏输赢。

本轮额外只读采集了18,609条余额快照、1,448条现存操作记录及78条日累计；同时检查了服务器既有SQL备份目录。操作记录滚动保留7天，快照没有完整记录每次结算当时的桌台兑换比；当前配置不能无条件当作历史配置。原始快照、恢复记录、重复/缺失进入记录也需要按会话核对，不能仅对首末余额作差后全量回填。

已经证实的两场大白兔分别为+2,363币和+2,326币，后者旧上报折算后只有+2,166币。它们用于本轮真实方法回归，不据此推算该玩家全部历史。历史修正应在独立副本逐会话核算、列明可恢复和存疑范围，再审核具体回填值；本轮没有执行UPDATE或清空旧盈亏。**仅发布代码不能使既存历史总盈亏自动正确。**

原始线上证据在 `.build/winloss-audit-full.jsonl`、`.build/winloss-audit-ledger.jsonl`；前次只读核查结论见 `Docs/线上玩家盈亏数据核查-20261102.md`。
