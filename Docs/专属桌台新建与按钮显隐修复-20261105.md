# 专属桌台：按钮显隐修复、专属视图新建、麻将胡了改称公共桌台参数（2026-11-05）

状态：已本地修改并验证，**未部署、未提交**。未操作线上、未执行 SQL、未重启服务。

## 需求

1. 游戏配置里选游戏类型 → 游戏 → 某条线，可一键「从公共桌台复制一套」、一键「收回专属桌台」；已有专属桌台的线还能继续新增专属桌台。
2. 没设专属桌台的线默认用公共桌台。
3. 麻将胡了没有桌台：代理下拉里的「默认」改称「公共桌台参数」；只提供「复制公共参数配置」「收回独立参数配置」，独立参数配置可直接修改保存。

## 发现的问题（线上 1.0.104/1.0.105 都受影响）

`ff261cf1`（11-03 麻将代理线配置）在 `gcMjhlApplyMode` 里加了一行
`$('#gcNewTable,#gcDelete,#gcRefresh,#gcLineCopy,#gcLineRecall').toggle(!on && !gcCurLine())`，
而 `gcLoadTables → gcApplyType → gcMjhlApplyMode(false)` 每次加载桌台都会执行它，且之后没有任何代码再按代理线状态恢复按钮。用真实页面复现（旧版 HEAD）：

| 视图 | 复制 | 收回 | 新建 | 删除 |
|---|---|---|---|---|
| 公共桌台 | **显示（点了无反应：没选线，函数直接返回）** | **显示（同左）** | 显示 | 显示 |
| 选中某线 | **隐藏** | **隐藏** | 隐藏 | **隐藏** |

即：选中线后复制/收回按钮根本看不到；公共视图里能看到但点了没反应、也没有确认框。这比 11-04 定位的确认框懒加载问题更直接，11-04 的修复只覆盖了其中一种可能。

## 修改

- `ConfigEditor.cshtml`
  - 按钮显隐只由 `gcApplyLineUi` 决定；`gcMjhlApplyMode` 改为调用它，`gcApplyType` 去掉重复的新建按钮开关。
  - 规则：公共视图——新建/删除/刷新，无复制/收回；选中线且无专属桌——只有「从公共桌台复制一套」；选中线且有专属桌——收回/新建/删除/刷新；麻将胡了模式隐藏全部普通桌台操作。
  - 专属视图允许「新建桌台」（含批量），标题显示「新建 N 张【线】专属桌台」；该线还没有专属桌台时提示先复制。新建/删除后先刷新代理下拉的专属桌数再刷新列表。
  - 麻将胡了文案：默认 → 公共桌台参数；复制默认配置 → 复制公共参数配置；恢复使用默认配置 → 收回独立参数配置；状态/提示/确认框同步。
- `YYT.BLL/EF/LineTables.cs`：新增 `ReserveNewLineTable` / `ReleaseUnusedReservation`。专属新建桌号接在最大桌号之后（不复用已收回桌号，那些桌的按桌行仍在），**写桌台参数前先登记归属**，保存后的 RP/PC 热更下发时这张桌已是该线专属，不会有一瞬间作为公共桌被其他线看到。拒绝：该线无专属桌、非直属代理、`#`/空、麻将胡了、超过 256 桌。
- `GameConfigController.SaveTableConfig`：原“专属视图禁止新建”改为预登记；牌机/押注/鱼机与拉霸两条保存路径都使用预登记桌号；`finally` 里如该桌号最终没写成桌台（任何提前返回或异常）就撤掉登记。
- `GameConfigMjhlAgentController` / `MjhlAgentConfigStore`：麻将接口返回文案同步改名，逻辑不变。

服务端无需改：`LineScope::TableVisible` 本就按“本线有专属桌只看本线，否则只看公共、已收回谁都看不到”判定，满足需求 2。

## 补充：匹配一致性检查（同日）

逐段核对“桌台归属线 ↔ 玩家所属线”：

| 环节 | 口径 | 结论 |
|---|---|---|
| 页面 → 复制接口的参数类型 | 下拉 `data-type` 取 paraType（麻将54为3） | 一致；接口现以 `games.GameType` 换算复核，对不上拒绝 |
| 玩家所属线 | 中心服沿 AGENCY 上溯到 PRIV=1 的 `admin.ID` 原样 | 一致 |
| 游戏服可见/入座 | `FilterTableConfigs`、`CanSit` 同用 `TableVisible`，**逐字节比对** | 一致 |
| 后台判定/中心服 `LineHasOwnTables` | MySQL 比较，**不分大小写** | 与游戏服口径不同 → 风险点 |
| 客户端桌位 | 位置→真实桌号取自服务端过滤后的配置块，入座发真实桌号 | 一致 |

风险：若归属写成与 `admin.ID` 大小写不同的写法，后台列表里看得到专属桌，中心服也认为该线有专属桌，但游戏服匹配不上 → 该线玩家只看到公共桌，专属桌谁都用不了。修复：复制与专属新建一律写入库里 `admin.ID` 的原样写法（不再沿用请求或旧行写法）。临时 MySQL 验证增至 193 项（含按 `LINEB` 请求、落库为 `lineB`）。

线上已有数据请用只读脚本 [Tools/db/check-line-ownership.sql](../Tools/db/check-line-ownership.sql) 核查（2026-11-05 从原 Docs/sql 路径迁入工具目录；写法不一致/代理失效、孤儿归属、同线多种写法）；本段原验证时的本机 `mth` 库未执行代理线补丁，无法代查。
