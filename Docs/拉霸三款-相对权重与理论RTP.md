## 后台入口

游戏配置 → 选择明星97／水果机／水浒传 → 选择已保存的机台 → **拉霸出货权重与理论 RTP**。

勾选“启用相对权重开奖”，调整目标奖型的整数权重。明星97按每10000次、水浒传按每100000次填写；未中奖＝口径减中奖奖型合计，自动计算。水果机24灯为相对权重，每项最高10000；0表示不抽取，概率为该灯权重÷24灯合计。输入改变约300毫秒后自动预览，在顶部显示基础奖、额外玩法、总理论RTP；不限制RTP必须小于100%。

额外玩法按游戏分别展示：明星97没有明星倍／BONUS／系统奖；水浒传小玛丽固定开启，可调整24个外圈停位相对权重与27至512回合上限，进入条件是九线中从任一端连续3／4／5个水浒传万能图标，分别送1／2／3次，各线相加最多27次。水果机没有免费局，可选择使用自定义幸运灯奖池；关闭时仍按随机送1至5灯或吃灯各半。水果额外显示八个下注区域RTP；不等额下注应按实际下注分配加权，不能把八区均值当作每区都相同。水果的两个幸运灯各自一套奖池：“右侧幸运灯（灯10/面板位9）”用 extra[1..11] 特殊奖 + extra[12] 吃灯，“左侧幸运灯（灯22/面板位21）”用 extra[28..38] + extra[39]；左侧 12 项全为 0 时沿用右侧那套，所以旧配置（只有 1..12 有值）行为不变。理论 RTP 按两灯各自奖池加权计算，与游戏服 `LabaWeightEngine::FruitType(c, lamp, rnd)` 同一口径。

点击 **保存本机台权重** 才落库并发送PC热更。仅修改输入不会写库。“基础桌台保存”与“权重保存”为独立入口，不会相互覆盖。新建机台须先保存基础信息。关闭新模式并保存后恢复旧算法及旧配置；未勾选时显示的是新模式试算，不是对旧配置的实测返奖率。

后台明确区分“保存成功但热更失败”和“热更指令已发送”。后者仍应查游戏服日志`[LabaWeights]`的目录指纹、table、enabled、totalWeight、extras，不能把指令送达中心服等同于游戏服已应用。保存超时可能已经落库，应重新读取核实后再操作。

## 计算和配置依据

核心为 `TTY.Web/Models/LabaWeightMath.cs`，页面组件 `_LabaWeights.cshtml`、交互 `game.labaweights.js`，接口在 `GameConfigWeightsController.cs`。计算目录 `TTY.Web/Config/laba-weight-catalog.json` 由服务端真实构造器生成，必须与服务端 `Common/LabaWeightCatalog.h` 配套，不能手工改平均倍数。

普通盘面目录均经过实际规则复算。明星97八线齐押、每局扣单线注×8，连线与全盘奖均按单线注；水浒传九线齐押、每局扣单线注×9，连线奖按单线注、全盘奖按总押注。两款出现全盘奖均不叠加线奖；水浒另外计入小玛丽有限回合与内圈奖励，明星97没有额外玩法。普通连线类别显示的“本类整盘平均”包含同盘其他中奖线，保留最多3位小数，与帮助中的固定单线赔率区分。水果按两灯各自奖池计算特殊送灯与吃灯，没有免费局。

完整数学公式、额外参数下标、传输字段和限制见配套服务端 `docs/拉霸三款-权重RTP重写.md`。理论值针对固定下注自然局；人为控牌、比倍、容量拒绝不包含在内，短期实际值也会波动。默认约90%仅为新模式初始试算基线，不是原包概率或已应用的运营配置。

复用既有`cardpayoutprofile`，事务仅修改该游戏该桌的HandType 1000至1279，不需要建表迁移。写接口有总台权限、防伪令牌与POST校验，审计包含操作者、机台、目录与配置。当前中心服配置单帧仍有容量上限，超预算会明确拒绝，不会静默丢机台参数。

## 最短人工联调步骤

本机未运行MySQL/IIS，数据库落库与真实热更仍需在隔离环境验收。建议使用无真实余额、无真实玩家的测试环境：

1. 部署配套后台、新客户端、中心服和三游戏服。后台包必须包含`Config/laba-weight-catalog.json`；先不启用运营机台的新模式。
2. 选一个测试机台，启用新模式，明星97／水浒所有中奖奖型设0，未中奖自动为10000／100000；保存后重新读取，确认值不漂移，游戏服日志该桌enabled=1，试玩应无自然中奖。仅用于隔离环境，不能对真实玩家使用该测试设置。
3. 将一个固定目标权重设为完整口径（明星97为10000、水浒传为100000）、其余0，确认理论值按单局总消耗折算；对比盘面和实际扣注/赢分。水果只保留一个普通灯，检查命中该灯及对应下注区域赔付。
4. 水果分别配置两侧特殊奖／吃灯；水浒传选择全盘万能，检查27次小玛丽、外圈与内圈奖励及最终余额；明星97确认额外玩法贡献为0。刷新页面确认数据库已保存。热更失败时页面必须提示未生效，不能报“下一局已应用”。
5. 另一个机台不得随之改变；关闭新模式后确认日志enabled=0并回旧算法。验证完成后恢复测试机台原值，不保留全输/必中奖测试配置。
