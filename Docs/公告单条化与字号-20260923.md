# 全屏公告单条化 + 字号（后台侧）- 2026-09-23

## 需求

客户端只展示一条公告，后台「全屏公告」页因此大改：

1. 去掉「添加公告」按钮，进入页面即编辑那唯一一条公告；
2. 后台只能设置唯一公告（不允许存在多条）；
3. 设置公告时可以设置字号；
4. 客户端默认居中展示公告，后台编辑时也要居中预览；
5. 后台编辑窗口与客户端 `Notice` 面板的 `Scroll View` 1:1 对应。

## 字号怎么下发到客户端（关键设计）

中心服 `ServerCenterNew::MessageNotice` 只把 `TITLE` / `NOTICE` 两个字符串下发给客户端
（**报文里没有字号字段**，`Database::GetNotice` 也只读这两列），所以不动中心服的前提下，
字号只能搭在正文里：

```
NOTICE = [SIZE=nn]正文…    -- 字号 ≠ 41 时由后台写入
NOTICE = 正文…             -- 字号 = 41（默认，与客户端 Label 设计值一致）时不写
```

- 默认字号不写标记 → **运营没动过字号时，老客户端（不认标记）完全无感**；
- 一旦把字号改成非 41，未更新的客户端会把 `[SIZE=55]` 原样显示出来，所以页面上做了
  二次确认提示（保存按钮会弹出带说明的确认框）；
- 想彻底去掉这个"搭车"机制，需要中心服在报文里补一个字号字段（属游戏服仓库改动，本轮未做）。

## 页面与客户端 1:1 对应关系

后台预览的可视区、正文列宽、字号、行高、字距、颜色、描边、字体全部按客户端
`Notice/Scroll View` 的序列化值复刻（对照表见客户端文档第 3 节）：

- 可视区 **648 × 310**（`overflow: hidden` 的滚动容器，隐藏滚动条——客户端也不画滚动条，
  而且浏览器默认滚动条会占 15px 使正文在可视区里偏移，实测 648 会变成 633）；
- 正文 **624** 宽、`margin: 0 auto` + `text-align: center` 水平居中、距顶 **10px**；
- `font-size = 字号`、`line-height = 字号`（NGUI `finalLineHeight = fontSize + spacingY(0)`）；
- `letter-spacing: 2px`（`UILabel.mSpacingX`）、颜色 `#DBF2FF`、黑色 1px 四向 `text-shadow`（Outline）；
- 字体 `NowarSansCN`（站点 `Content/fonts/NowarSans-CN-Bold.otf`，`@font-face` 加载，回退中文黑体）。

预览区宽度写死 648 且 `flex: 0 0 auto`，不会被 flex 压缩；内容宽度 ≥1440 时与左侧表单并排，
更窄时自动换到下方（并排时预览 `position: sticky` 吸顶）。

> ⚠️ 预览是"设计分辨率 1:1"：客户端 UI 是 NGUI `UIRoot`（Constrained，manualHeight 720），
> 真机按分辨率整体缩放，所以这是与 Unity 编辑器参考分辨率一致的 1:1，不是真机像素 1:1。

## 1.0.50：运营反馈「后台设置后客户端公告是空的」排查与修复（2026-09-23 03:03 已上线）

**现象**：运营在后台设了公告，客户端公告面板还是空的。

**排查结论（都不是客户端/下发链路的问题）**：

| 检查项 | 证据 |
|---|---|
| 客户端连哪台 | `Network.DefaultServerIp = 8.218.67.82`、`DefaultWebBaseUrl = https://x.52.dyj.wang`（Lua 里的 `47.239.65.23` 是会被 `ApplyServerAddress` 覆盖的旧值）→ 客户端读的就是本后台这套 `mth` 库 |
| 库里有公告吗 | `SELECT COUNT(*) FROM notice` = **0 行**（改前、部署后、排查全程都是 0） |
| 后台有没有保存过 | IIS 访问日志最近 3 天 `POST /Game/Notice/*` 只有 `GetNotices`（旧页）+ `GetNotice`（新页）两种**读取**请求，**一次 `AddNotice`/`updateNotic`/`SaveNotice` 都没有** |
| 保存接口本身通不通 | 只读会话直接 POST `/Game/Notice/SaveNotice`（空内容/越界字号/超长三种非法载荷）→ 都返回正确的校验提示，未写库 |

**根因**：`保存公告` 的确认框走 `window.confirm`（`common.js`），它内部是 `easyloader.load('messager', …)` —— 而 messager 还牵一整条依赖链
（`dialog → window → resizable/draggable/panel`、`progressbar`）。页面**只在点击那一刻**才首次拉这条链；线上经 CDN 时这条链会慢/卡
（实测 `easyloader` 的回调 30 秒都没触发、`jQuery.messager` 一直是 undefined），于是**点击静默失效**：不弹框、不发请求、页面也没提示，
运营以为"保存过了"，客户端自然还是空的。本地 IIS Express（无 CDN）链子秒级完成，所以本地测不出来。

**修复（1.0.50，只动视图）**：

1. 进页面就 `easyloader.load(['linkbutton', 'messager'], …)` 预加载确认框依赖链，运营点保存时已就绪；
2. 新增 `confirmReady()` 兜底：模块万一还没就绪，用 DOM 版 `showToast` 明确提示"提示框组件还在加载，请 1-2 秒后再点一次"，
   不再静默失效（`保存公告`/`放弃修改`/两处校验 alert 都走这个守卫）。

**上线后复测（线上真机）**：进页面即有 `jQuery.messager`；点「保存公告」→ 弹出「确认保存公告？」→ 点「取消」不写库；
线上仍然 `notice` 0 行（全程没写测试数据）。`WebVer = 1.0.50`，站点备份 `C:\Backend_backup_20260923_030304`。

**给运营的操作口径**：后台 → 管理后台 → 全屏公告 → 填内容（标题可留空）→ 点「保存公告」→ 确认框点「确定」→
玩家下次进大厅/登录就能看到。**字号先别改**（保持默认 41），等客户端新包上线后再用。

## 遗留 / 待确认

1. **字号标记是临时通道**：若要改成协议字段，需中心服在 `0xAA0E` 报文里加字号并同步客户端解析。
2. **标题（TITLE）保留但已弱化**：客户端只展示一条公告时标题不再有列表用途，
   但中心服以标题作为 `map<标题,正文>` 的 key、数据库列也非空，所以页面上仍保留（留空存「公告」）。
3. **其它大厅皮肤**（YL/HKSZ/KLYG/LXH 等）的 Notice 面板是旧排版（字号 25、左对齐、可视区 648×374），
   预览基准取的是当前在用的 `DaTingG178.unity`；若某个皮肤也要 1:1，需要按该场景再核一遍参数。
4. **公告保存后没有实时推送**：中心服在客户端请求时按需读库，玩家下次进大厅/登录才看到新内容
   （中心服的 `RN` 推送通道是空实现，本轮未动）。
