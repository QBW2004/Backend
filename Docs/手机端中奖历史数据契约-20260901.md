# 手机端中奖历史数据契约

手机端中奖历史页读取 `gameprizerecord`。牌机展示开奖记录，鱼机/拉霸只展示触发中奖播报的高倍率记录。该表必须由游戏中心服在结算事件完成时写入，Web 后台不根据当前控制状态反推“是否送奖”。

## 写入规则

- `EventId`：结算事件唯一编号，重试时保持不变；数据库唯一键保证幂等。
- `UserID`、`GameId`、`GameType`、`RoomId`、`TableId`、`CardType`、`Multiplier`、`Score`：使用本次结算的最终结果。
- `IsBroadcast=1`：仅当同一结算分支实际触发客户端中奖播报时写 1；未播报写 0。
- `IsManualControl=1`：牌机/拉霸仅当最终采用后台手动控牌牌型送出时写 1，只是存在控制记录但未采用时写 0；**鱼机为放水口径——放水控制（单人放水 UC02 / 总放水 mode5）实际作用于该玩家期间击杀的高倍率鱼写 1**（判定取击杀时游戏服 `mCtrlType==SERVER_CTRL_OUT && mCtrlValue>0`，即放水概率档真的套用到该炮，而不是仅存在放水记录），其余击杀写 0。页面「是否送奖」列直接按此字段回显。
- 两个标志都必须由结算事件明确写入；不要依赖数据库默认值表示业务语义。
- `RecTime`：结算完成时间。

示例（字段值由中心服结算上下文提供）：

```sql
INSERT INTO gameprizerecord
    (EventId, UserID, GameId, GameType, RoomId, TableId, CardType,
     Multiplier, Score, IsManualControl, IsBroadcast, RecTime)
VALUES
    (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
ON DUPLICATE KEY UPDATE EventId = VALUES(EventId);
```

手机端接口只返回已启用且非押注游戏的记录，并在查询前校验玩家所属代理线。
