# 专属桌台复制、收回点击无响应（2026-11-04）

状态：已本地修复并验证，未部署。线上只读核查，未登录、未提交复制/收回、未执行 SQL、未重启服务。

## 原因与证据

用户确认两个按钮均“点击没反应，连确认框也没有”。`ConfigEditor.cshtml` 的 `gcLineCopy` / `gcLineRecall` 都要等共享 `window.confirm` 的确定回调才发 POST。

旧 `Scripts/app/common.js` 每次确认都先调用 `easyloader.load('messager', ...)`。`Scripts/easyloader.js` 的模块等待分支累计等待超过 `timeout=2000` 后不再执行回调；脚本下载失败也没有 `onerror` 通知。因此页面正在加载 numberbox 等共用依赖时，确认链可能静默中止，既无弹窗也无接口请求。

线上 WebVer=1.0.104。线上 common.js、easyloader.js 与修复前本地文件 SHA256 完全一致。最近 3000 行 IIS 日志中 CopyPublicTablesToLine / RecallLineTables 请求均为 0；这是近期日志检查，不代表全部历史请求。证据：`.build/line-table-confirm/live-readonly.json`。

真实 Chromium 使用生产 EasyUI 文件、共享 common.js 和原页面两个操作函数，延迟 linkbutton 2600ms 与返回 404 均复现旧版无弹窗、无 POST。未复用此前预览工具的全量预加载 EasyUI，因此能覆盖实际懒加载路径。

## 修复

仅产品文件 `TTY.Web/Scripts/app/common.js`：在覆盖 `window.confirm` 前保存浏览器原生方法。EasyUI 确认框已就绪时继续使用原弹窗；未就绪时直接调用浏览器确认框。两种路径保留确定/取消回调，取消不提交，也不启动会迟到重放的异步确认加载。
