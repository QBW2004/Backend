## 流程与保留规则

1. 复用 [export-db.ps1](../Tools/db/export-db.ps1)，以 `--single-transaction --hex-blob --routines --triggers --events --set-gtid-purged=OFF` 导出完整 SQL，包含全部表结构和数据。此次未修改该文件已有的工作区改动。
2. 文件命名 `mth_yyyyMMdd_HHmmss.sql`，源端检查退出码、非空与 SHA-256。密码仅传给当前导出进程环境，不写入原生命令参数。
3. 上传为 `.sql.partial`。接收程序检查文件名、日期、普通文件类型、非空与 SHA-256，再原子改为 `.sql` 并写 `.sha256`。重复上传只有内容相同才接受。
4. 仅在新备份成功校验后，清理本任务日期窗口外的正式 SQL/校验文件；源端同时清理对应旧日志和结果文件。失败保留已有备份，因此故障期间可能暂时超过 3 天。临时上传文件不作为有效备份，不通过成功清理去删除未核验文件。
5. 清理不递归、不跟随符号链接、不处理目录中无关文件。按文件名中的北京时间日期计算，不依赖传输修改时间。

备份为在线单事务导出，不停止后台、中心服或游戏服，不连接游戏管道。备份期间应避免 DDL。当前方案未配置 binlog 时间点恢复、外部消息告警或游戏服文件存档备份；失败查看计划任务退出码及源端结果/日志。`mth_full.sql` 与 `mth_clean.sql` 未被本次定时备份覆盖。
