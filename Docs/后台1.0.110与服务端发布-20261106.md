## 发布后发现的缺陷与热修（17:33）

**现象**：直连中心管道发 `QN` 能通（协议与命令正确），但快照恒为 `{"AvailableGames":[],"Players":[],"Version":1}`。后台 `QueryAnnouncementOccupants` 因 `AvailableGames` 不含任一 gameId 恒返回 null → 机器人中奖播报一律拒播（fail-closed，不崩、不影响真人播报与资金）。

**根因**：`GenerateAnnouncementOccupancyJson` 枚举 `mGameComHandlers`，该表只由 `CenterComHandler::ServerGameLogin` 写入；而 `ServerCenter.cpp` 里 8800 端口的 `SocketAcceptor<CenterComHandler>` 早已注释停用，子游戏实际经 `RunGameSocket`（8000+gameID*10 双口）接入并登记到 `gameSockets`（`mutexGameSockets` 保护）——`mGameComHandlers` 恒空。

**修复**：`AvailableGames` 改为在独立作用域持 `mutexGameSockets` 枚举 `gameSockets` 键（该锁不允许与其它锁嵌套，故先单独取完快照再进 `g_myLock` 遍历 `mapUser`，逻辑不变）。仅 `ServerCenterRun.cpp` 一处，无协议/SQL/后台变更。

**热修执行**（`C:\MTH-Deploy\hotfix-qn-availgames\deploy-hotfix.ps1`）：17:33:26 预检在线 0 → 备份线上中心 exe/PDB → daemon 停 Robot 与全部服务 → 只换 `ServerCenterNew.exe/pdb` → 全启 + Robot → 16 唯一进程、新 exe 哈希一致 → 17:33:57 `HOTFIX_DEPLOYED`。

**热修后核验**：`QN` 回复 `{"AvailableGames":[3,55,15,44,13,37,5,16,10,2,25,54,40,53],"Players":[],"Version":1}` —— 14 款在服游戏全部在列，与 `games.Enable` 一致；`Players` 为空正确（当时无真人在座）。新 exe SHA256 `DBA3EFE043AE12A66EBC4F1A2BE682C8D1CEE7CED4D607F743785DA3CC605B11`。

**排查备忘**：中心文本命令以 `\0` 结尾（`PipeFrameLength` 取首个 NUL），回复为 JSON + `\n`；PowerShell `WriteLine(object[])` 会把数组写成 `System.Object[]`（中心日志 `Rec:Sy`），须显式 `[char[]]` 逐字符写 `QN\0\r\n`。中心日志 `Rec:` 只记前两字符。
