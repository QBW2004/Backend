# 机器人座位管理与每日打乱（2026-10-31）

## 交付范围

机器人设置页新增一张“当前机器人座位”表，直接读取 ServerRobot 的实时快照，显示机器人账号、游戏、代理线、机台、座位、连接状态和入座状态。每行支持“移除座位”和“指定座位”。原来的 `robot_seat` 配额表仍用于人数/线路配置，两者分开显示。

页面顶部增加：

- **打乱机器人**：填写 1～5 秒的最小/最大间隔后确认。ServerRobot 会逐个让当前机器人离座，随后按随机间隔重新创建；牌机和拉霸重新寻找本线空机台，其他游戏沿现有机器人计划重新分配。正在打乱时，移除/指定/热更不会并发修改机器人集合。
- **每日定时打乱**：启用后每天在开始/结束时间窗口内执行一次；开始时间大于结束时间表示跨午夜。间隔保存为 1～5 秒。

## 管理接口

后台 `RobotController` 新增：

- `GetRobotSeats`：读取实时状态并补充游戏、机台名称和代理线。
- `RemoveRobotSeat`：发送 `REMOVE <robotId>`。
- `ShuffleRobots`：校验 1～5 秒后发送 `SHUFFLE <minMs> <maxMs>`。
- `GetRobotSeatOptions` / `SetRobotSeat`：读取可用游戏、代理线、机台和座位，并发送 `MOVE <robotId> <gameId> <roomId> <tableId> <seatId> <gameType>`。
- `GetRobotShuffleSchedule` / `SaveRobotShuffleSchedule`：读取/保存每日窗口。

写接口保留后台成员权限、Ajax 校验和超管权限门；目标游戏、启用机台、座位容量及代理线归属在后台再次校验。

## ServerRobot 管道协议

- `STATUS` → `{"robots":[...]}`，包含实时座位和计划座位。
- `REMOVE <id>` → `REMOVE_OK` / `REMOVE_NOT_FOUND`。
- `MOVE <id> <game> <room> <table> <seat> [gameType]` → `MOVE_OK` / `MOVE_FAILED`。
- `ONLINE <id> <game> <room> <table> <seat> [gameType]` → `ONLINE_OK` / `ONLINE_FAILED`；用于把未在运行池中的 `userrobot` 账户刷新并上线入座。
- `SHUFFLE [minMs maxMs]` → `SHUFFLE_OK` / `SHUFFLE_BUSY`。
- `SCHEDULE_GET` → `SCHEDULE_JSON {...}`。
- `SCHEDULE <enabled> <start> <end> <minMs> <maxMs>` → `SCHEDULE_OK` / `SCHEDULE_BAD`。

每日设置持久化到 ServerRobot 的 `robot.ini`：`shuffleEnabled`、`shuffleStartMinute`、`shuffleEndMinute`、`shuffleDelayMinMs`、`shuffleDelayMaxMs`。启动时读取，修改后原子替换配置文件。

## 运行口径

“移除座位”和“指定座位”是运行时操作：当前 ServerRobot 进程内立即生效。它们不会把某个账号写入 `robot_seat`，因为现有表只保存线路/机台配额，没有机器人账号绑定字段；ServerRobot 重启或执行全量 RT 热更后，会按 `robot_seat` 重新建立计划。每日打乱和手动打乱同样只改变运行时座位，不改配额。

## 2026-11-01 1.0.90 机器人账户批量创建与删除

合并后的机器人管理页新增“批量创建账户”和“删除选中账户”。下方账户表支持复选框多选，批量删除把选中的 `userrobot.ID` 一次提交给服务端事务删除，不再在浏览器逐行发起删除请求。
