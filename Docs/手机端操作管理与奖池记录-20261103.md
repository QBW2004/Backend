## 7. 奖池扣款口径

- `Docs/sql/奖池精准扣除与明细保留-20261103.sql` 重建两个存储过程：
  - `agentprize_record_award`：送奖开奖按上报的本手牌型得分扣，余额不足**扣到 0 为止**；`AwardDiamonds` 记玩家实得，`BookedDiamonds`/流水记实际扣除。
  - `agentprize_release_delta`：放水累计净收益最多扣到 `TargetCoins`，余额不足同样扣到 0；输回时正常返还。
  - 控牌与放水重叠返还沿用原口径，补扣方向同样不使余额为负。
- 送奖下发只要求奖池余额 > 0（用户确认：送出得分大于余额也可送，扣到 0）；放水仍要求余额覆盖目标。
- 服务端（`MTH-Server`）：`ServerCardDazhi`/`ServerCardKing3`/`ServerCardPhenix`（含大白兔）的 `ReportPrizeRecord` 新增 `funded` 参数，**比倍爆机、全兔赛跑、全民赛跑**只记中奖明细/播报，不再按送奖控制编号扣奖池（用户确认彩金/额外得分不计入送奖支出）。麻将胡了按实际送出得分扣，不改。

## 2026-11-06 补充：充值弹窗改为“充值 / 提取”两个按钮（未提交、未发布）

**问题**：原弹窗用负数（`-N`）表示退回我的钻，但金额框 `inputmode="numeric"` 在手机上弹出纯数字键盘、没有 “-” 键，负号打不出来。

**按运营确认的方案**：金额框恢复为只能输入数字；底部原 “确认充值” 的位置改为并排、等宽、间隔 12px 的两个按钮：**充值**（蓝 `#007aff`，我的钻 → 奖池）和**提取**（红 `#ff3b30`，奖池 → 我的钻）。中途试过的 “±” 切换按钮方案已撤掉。

**改动**
- `phone.control.js`：金额框 `type="text" inputmode="numeric" pattern="[0-9]*"`，输入时全角数字转半角、其它字符（含 “-”、小数点、字母）直接去掉。按钮值 `in`/`out`，`out` 提交 `Withdraw=1`。仍走原 `PrizePool/Transfer` 接口与 GUID 请求号。前端校验：空/0 提示 “请输入大于 0 的整数钻数”；提取超奖池提示 “奖池余额不足，当前奖池 N 钻”；充值超我的钻提示 “我的钻石不足，当前 N 钻”，这三种都不发请求。成功提示 “已从奖池提取 N 钻到我的钻石” / “奖池充值成功”。点遮罩关闭，不展示取消按钮。
- `Control.cshtml`：`.pool-modal .modal-footer { gap: 12px; }`，两个按钮 `flex: 1 1 0`，`pool-in-btn` 蓝底、`pool-out-btn` 红底，白字。
- `B_PrizePool.Transfer`：余额不足时分别返回 “奖池余额不足，当前奖池 X 钻，无法提取 Y 钻！” / “我的钻石不足，当前 X 钻，无法充值 Y 钻！”（原来统一为 “可用余额不足！”）。整笔拒绝，不截断成扣到 0；奖池已为负（放水超额）时同样拒绝。权限、只操作本人奖池、请求号防重、同一事务更新 `admin.COINS`/`agentprizepool`/`agentprizeledger` 都不变，流水 Kind=2（代理流水显示 “退回我的钻”，负数）。
- 契约测试 `ViewContractTest` 第 10 项（`MobilePrizePoolOperationRound20261103`）和第 9 项（`MobileOperationPagesFollow20261104Adjustments`）改为断言新的输入框和两个按钮。
- 电脑端：没有奖池充值入口（全仓只有手机端调用 `PrizePool/Transfer`），无需同步。
