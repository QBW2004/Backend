# 拉霸机器人按总数设置（2026-10-31）

> 2026-11-06 后续：鱼机和押注已在本地改为总数＋每桌上限，替代下文“继续按桌设置”的历史描述，尚未上线；见[新实现与配套SQL/Robot依赖](鱼机押注机器人总数与每桌上限-20261106.md)。本页拉霸历史发布事实保留。

状态：后台与 Robot 已实现并验证，未发布。

## 使用方式

「机器人设置 → 添加机器人 → 拉霸类」选择明星97（16）、水果拉霸（40）或水浒传（53），再选公共桌台或代理线。与牌机相同，隐藏桌号，回填当前机器人数量，填写本线目标总数（0～启用机台数）。保存可增、减或清零；Robot 随机遍历本线空机台，一台一人，满台保留名额等待，不顶掉已占位机器人或真人。

## 实现与兼容

- 后台复用现有容量查询、`SetCardRobots` 事务与 `robot_seat` 存储；这些历史名称保留兼容，牌机和拉霸通过 `IsMachineRobotGame` 共用入口。新拉霸行保留 `GAME_TYPE=3`，保存后按原 RT 链路通知 Robot。
- 上限由当前代理线启用机台数计算；游戏行锁串行校验并发请求。普通代理线/公共桌台独立，麻将胡了仍排除，押注和鱼机继续按桌设置。
- Robot 将 GameType=3 接入牌机已有的容量规划、代理线候选读取、随机遍历、失败重试与热更候选刷新；已有三款拉霸游戏服通过原子占位拒绝重复入座，无需更换三款游戏服。
- 原按桌多人数行可读入汇总；保存时按差额增减，超过现有容量的旧配置可直接减到合法总数或清零。Robot 同样按本线容量约束旧行，所有候选都来自本线启用机台。
- 不新增表、字段或 SQL 迁移；未自动改动任何线上机器人目标、桌台、权重或资金。未访问生产保存接口或执行线上部署。

## 发布与验收

需配套隔离发布后台（页面、YYT.BLL/YYT.Web 程序集）与 ServerRobot；现有 Robot 版本仅对牌机启用随机机台，不能只发后台。保留中心服、三款拉霸游戏服及其余游戏进程。发布前按项目既有流程确认运营授权、备份与核对线上版本，不能使用先前 1.0.74 的旧包。

上线后刷新后台，依次选择三款拉霸，确认不再选桌号且当前总人数正确。选择运营认可的游戏和代理线填写目标总数并保存，重开弹窗核对回填；客户端观察机器人仅在本线空机台入座。分别验收减人、清零和满台等待，最后恢复运营期望总数。此步骤实际增减线上机器人，应由运营选择目标与时间。
