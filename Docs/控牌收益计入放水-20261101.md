# 控牌收益计入放水（2026-11-01）

状态：已实现并通过本地验证，未发布。需后台与中心服配套隔离发布；无需 SQL 迁移、子游戏或客户端改动。

## 行为

- 存在执行中的放水记录时，所有游戏的实际净收益都计入 `usercontrolstatus.GrantedCoins`，包括牌机、三款拉霸、麻将胡了的控牌收益。保持原来的净收益口径：押注 10 分、派奖 100 分，已放水增加 90 分；亏损抵扣进度，可为负数。
- 从子游戏累计盈亏同步包求增量，重复收到同一累计值不会重复增加。使用实际结算，不以后台指定牌型的理论倍率或中奖历史记录代替。
- 控牌最后一次即使先回写次数为零，其结算仍计入；随后实际结算的免费/附加奖励在放水记录尚未完成时继续累计。麻将沿用实际钱包折算后上报的分值，不额外取整。
- 已放水达到或超过目标时，保存本次完整净收益并完成放水；不会裁剪奖金，也不会取消尚未执行完的控牌次数。完成之后的新结算不再增加该条放水记录。
- 在牌机、拉霸、麻将内也可以设置放水目标，进入/切换这些游戏不会令放水记录过期。这些游戏只累计进度，放水强度仍仅在鱼机/押注游戏应用。
- 设置控制及进入游戏时清除无总控记录的负缓存，避免原有 5 秒缓存漏掉刚设置后的首局。
- 无执行中放水记录时不新增已放水分数；吃分/放水互斥、控牌共存及页面控牌优先展示规则保持原口径。历史已完成/失效记录不自动复活，之前漏计的收益不回填。

## 实现位置

- 后台 `YYT.BLL/EF/TotalControlRules.cs`：开放游戏的放水目标设置能力；`B_UserControl.cs` 注释同步。
- 中心服 `ServerCenterNew/ServerCenterRun.cpp`：`CheckTotalControlOnSettle` 移除鱼机/押注限制；`ApplyTotalControlNow` 对牌机/拉霸只保留进度、不发送覆盖控牌的设置或解除包；进游戏及能力校验保留这些游戏的放水记录；设置/进游戏清除负缓存。
- 无数据库结构或存储 SQL 修改。前端继续读取同一个 `GrantedCoins` 字段。

## 发布后人工验收

1. 用测试号在后台设置放水目标 1000，记下放水记录的已放分；再设置任一牌机/拉霸/麻将控牌，完成一局，按实际派奖减押注核对该记录的增量。控牌期间单人状态只显示控牌，可在控制记录中筛选放水核对。
2. 等最后一次控牌结算后再核对一次，确认未漏计；有免费/附加玩法时，在目标未达到的情况下继续结算并核对累计。
3. 将目标设为较小值并保留多次控牌，使实际净收益越过目标；确认放水记录完成、已放分保留真实增量，剩余控牌次数仍继续执行。
4. 切换到另一款游戏，确认未完成的放水进度延续；解除放水后再结算，确认旧记录不再累计。
