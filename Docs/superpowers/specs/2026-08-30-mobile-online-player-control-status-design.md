# 手机端在线玩家控制状态展示设计

## 1. 目标

手机端后台“玩家列表”的在线玩家卡片中，当前玩家存在总控状态时，展示所有正在执行的控制状态；同一玩家的多个控制状态不得被覆盖或只保留一条。

截图仅作为视觉参考，状态内容以现有总控状态接口返回的数据为准。

## 2. 现有接口与数据流

1. 手机端通过 `/Game/UserInfo/GetOnlineUsers` 获取在线玩家列表。
2. 手机端使用 `/Game/UserInfo/GetActiveTotalControls` 批量查询这些玩家的执行中总控状态。
3. 状态按 `UserID` 分组，写入对应在线玩家对象后再渲染卡片。
4. 接口失败时保持在线玩家列表可用，卡片不显示控制状态，不能阻塞或清空在线玩家结果。

## 3. 展示规则

控制状态区域位于在线玩家卡片底部，仅在存在有效状态时渲染。

| `ControlMode` | 展示内容 |
|---|---|
| 4 总点杀 | `吃分中... 吃分目标 {TargetCoins} / 已吃 {ConsumedCoins}` |
| 5 总放水 | `放分中... 放分目标 {TargetCoins} / 已放 {GrantedCoins}` |
| 6 总控牌 | `控牌中... 控牌值 {LimitCoins} / 次数 {used} / {total}` |

其中控牌已使用次数为 `TargetCoins - CardNumber`，总次数优先使用 `CardTotal`，缺失时回退到 `TargetCoins`。金额使用现有手机端数字格式化函数，所有接口字段输出进行 HTML 转义。

当状态为空、模式不是 4/5/6、或控牌数据明确已耗尽时，不展示该条状态；同一玩家剩余的其他有效状态仍需展示。

## 4. UI 样式

新增独立的控制状态容器和状态行：浅灰背景、红色文字、圆角和适当内边距，保持与截图红圈区域相近的视觉层级。多条状态垂直排列，不使用单行截断。

## 5. 改动范围

- `TTY.Web/Scripts/app/phone/phone.players.js`：批量加载、按玩家归并、状态格式化和卡片输出。
- `TTY.Web/Areas/Mobile/Views/Home/Index.cshtml`：状态区域样式。

不修改数据库、控制业务逻辑和通用接口契约；不增加逐玩家请求。

## 6. 验证方案

- 静态检查：确认页面只发起一次批量状态查询，多个状态使用数组归并而非覆盖。
- 构建：运行 `Tools/dev/build.bat`，确认无编译错误。
- 手动验收：准备至少三类在线玩家数据：无控制、单条吃分、同时存在两条或以上控制；确认状态区域分别隐藏、单行展示、多行完整展示。
- 若中心服不可用，确认在线列表失败处理逻辑不被本次改动破坏。
