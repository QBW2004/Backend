# 麻将胡了：复制默认配置、恢复使用默认配置

状态：2026-11-04 已本地实现并验证，未发布。本轮未操作线上。

## 操作行为

麻将胡了使用代理线参数表 `mjhl_agent_config`，以 `*` 表示默认配置。游戏配置顶部新增两个按钮，按该代理线当前状态显示：

- **复制默认配置**：将当前已保存的默认参数、普通/免费权重、筹码与兑换规则复制为该代理线的独立配置。以后修改默认配置不会影响该线。沿用来源配置已保存且匹配数学指纹的 RTP 摘要，无须重复计算相同权重。
- **恢复使用默认配置**：收回当前代理线的独立配置，重新跟随默认配置及其后续更新。保留收回前完整参数和操作人、时间、版本历史。

仅超管可操作；选择“默认”自身时隐藏两个按钮。默认配置尚未保存时不能复制或收回。两个操作都先二次确认，确认后提交并发送 PC54 热更新，未保存的页面修改会放弃。正在做 RTP 复核不妨碍直接复制已保存默认配置或恢复默认。

未配置代理的读取逻辑同时改为返回实际已保存的默认配置，与游戏服 `Snapshot::Find` 的回退口径一致；此前页面返回出厂值，与游戏服实际默认值可能不同。下拉和状态区明确显示“独立配置”/“使用默认配置”。普通桌台的归属表和机器人配置不变。

## 实现与并发保护

- `GameConfigMjhlAgentController.cs` 新增 `CopyMjhlDefaultConfig` / `RecallMjhlAgentConfig`，要求 Ajax、POST、防伪令牌、超管权限，并验证直属代理及麻将胡了开放范围。
- 操作提交目标代理版本与默认来源版本。默认来源或目标已改变时拒绝旧请求；默认行不能被收回。
- `MjhlAgentConfigStore.cs` 所有配置写入统一按默认行→目标行加锁，配置变化和历史记录同一事务提交。历史写入失败时复制/删除一并回滚。
- 收回会删除当前配置行，同时在既有历史表追加下一版本及收回前快照。后续复制、普通保存继续递增历史版本，防止旧页面在收回/重新创建后覆盖新配置。无需新增表或迁移。
- 游戏服现有 PC54 路径重发全量代理配置快照；快照提交后缺少独立行的代理按 `*` 回退。本轮不修改游戏服。
- 页面区分目标版本与实际来源版本；恢复默认后不冒用旧独立 RTP 缓存。刷新代理列表保留当前选择。提交期间禁用重复操作，15 秒请求超时可见提示，切换代理/游戏后丢弃迟到响应和确认。

## 发布边界与人工检查

需配套发布后台 `YYT.Web.dll/PDB`、`ConfigEditor.cshtml`，以及本聊天前一轮修复后的 `Scripts/app/common.js`，并递增 WebVer。无需数据库迁移、中心服/游戏服或客户端更新。

当前工作区还有其他待发功能：共享视图包含麻将 RTP 三秒估算，当前 Web DLL 包含大白兔/火凤凰 JSON 读取修复。发布时须按最终批准范围隔离编译/打包；若沿用当前视图，须同时带上其匹配的 `mjhl.agent.rtp.worker.js`。本轮未生成混装发布包，也未修改 WebVer。

发布后可在测试代理线上做约一分钟人工验收：

1. 选择麻将胡了及使用默认配置的测试代理，点击“复制默认配置”；取消应无变化，确定后显示“独立配置”，参数与已保存默认值一致。
2. 对该测试代理点击“恢复使用默认配置”；取消应保留独立配置，确定后显示当前默认参数，按钮切回“复制默认配置”。
3. 如需验证游戏内生效，使用该测试代理玩家重新进入游戏核对筹码/参数。热更新失败提示时先确认服务端状态，不以后台已保存代替游戏服已应用的验收。
